How the parts connect

Dashboard Kept ← Today

Three production interfaces and a small web review surface, one database. The daily run writes companies and scores into SQLite; everything else is a view or a thin write on top of that.

Data flow

  1. Google Sheet (Fund Criteria, Scoring Weights, Settings, Sources) is the editable brain. Each morning the pipeline reads it, validates every cell, and scores against that config.
  2. Sources fill the database with companies and evidence. The engine gates, scores, and tiers each one (shortlist / watchlist / reject).
  3. This web interface (Today + Kept) is where you review today’s queue and keep companies you like. Picks are stored here in the app.
  4. Telegram delivers the morning digest and maps chat commands (/today, /run, /status, …) onto the same CLI the timer uses. It does not hold a second shortlist.
Full self-serve detail also lives in docs/ops-guide.md in the repo — same content, for reading outside the app.

Shortlist vs Kept

  • Engine shortlist — score.tier = 'shortlist'. The system’s opinion. It moves when you change thresholds.
  • Kept — your picks. Press 1 (Worth contacting) or 2 (Unsure) on Today. Stored in SQLite user_field with field = 'verdict'. Open Kept any time; the header count is the same badge on Today.

Not for me is recorded for tuning but never appears on Kept.

Where Kept is stored

  • Primary: this app’s SQLite database, table user_field.
  • Google Sheet mirror: the Companies tab, column Z (Verdict), is updated as soon as a decision is saved here. A full sync-sheet run also backfills any missed write and folds sheet edits back into the app. You do not need Excel open to track your list.
  • Also feeds: founder-radar tune, which sweeps thresholds against your verdicts.

Update funds later

Edit the Fund Criteria tab in the sheet — one row per vehicle. Leave Fund key / Vehicle key alone on existing rows. Add a new fund by adding rows with new keys; set Active to FALSE to retire a vehicle without deleting history. After save, the next founder-radar run (or rescore) picks it up. Bad cells fall back to the last good value and show a red status note in the sheet.

Edit fund criteria & thresholds

  • Fund Criteria — geography, cheque range, age caps, hard rejects (key:value pairs separated by ·), sector plus/minus.
  • Scoring Weights — 0–4 matrix and attribute importance (blank = 1).
  • Settings — shortlist_fit, shortlist_edge, min_coverage, age/funding gates, region list, digest cap.

Add or remove sourcing channels

  • Turn off / on: Sources tab → Enabled TRUE/FALSE. No deploy needed; the next run skips disabled adapters.
  • Add a brand-new source: needs a code adapter under radar/sources/ registered in the sources registry, then a Sources-tab row. Enabling alone cannot invent a scraper.

Change the login password

This app sits behind a Caddy reverse proxy with basic auth. On the server, run caddy hash-password --plaintext 'your-new-password', put the resulting hash into RADAR_WEB_PASS_HASH in /opt/founder-radar/.env, then restart Caddy with systemctl restart caddy. The username is RADAR_WEB_USER in the same file. Never write the plaintext password into the repo, a chat thread, or anywhere else that is not the server itself.

CLI reminders: founder-radar doctor, founder-radar sync-sheet, founder-radar sources --list.
